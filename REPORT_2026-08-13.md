# Research Report — Closing the Pose-Conditioning Gap with a Closed-Loop GRU
**Date: 2026-08-13 · Branch: captain_gru_v3**

## The problem in one paragraph

Finetuning CUT3R on DROID wrist-camera data gives a strong baseline (arm A).
Conditioning the model's memory on the **ground-truth pose** of the current
frame (arm B) massively improves every pose metric — ATE drops from 0.076 to
0.013, rotation error 3.3× — while depth stays flat. The project goal: get
that benefit **honestly**, with no ground truth at test time, by predicting a
good-enough pose from information the model already has, using a GRU to
correct the fed-back pose before it re-enters the memory.

---

## 1. Things we tried

- **The conditioning ladder (A/B/C).** No conditioning (A), GT-pose
  conditioning (B), and honest feed-back of the model's own previous pose (C).
- **A lever — GRU input/head design.** Four combinations of input packing
  (pose vs pose+velocity) and head type (direct regression vs residual
  correction), plus a hybrid (A5) splicing the best halves.
- **G lever — gradient routing.** Detached per-step training vs backprop
  through time vs end-to-end gradient through the ray map vs both.
- **R lever — RAFT-style iteration.** Running the GRU cell up to 8 times per
  frame, re-feeding its own output.
- **F lever — image features.** Feeding the GRU visual evidence: pooled
  encoder features from one or two frames, through a bottleneck or raw,
  from four different feature producers (CUT3R's own encoder, ResNet-18,
  DINOv2, correlation statistics).
- **Oracle arms.** Same architecture, but GT slipped in at the GRU's input —
  measuring the ceiling if the GRU's prediction problem were solved.
- **Abstention gate (P2).** Per-scene switch to fall back to unconditioned
  behavior when conditioning would hurt.
- **Probe-pass (P4.3, the current arm).** Give the GRU a *second opinion*: a
  throwaway decode of the current frame **without** any fed-back pose, so the
  GRU sees an independent, image-based estimate of where the camera actually
  is — the one input that can observe drift.
- **The noise-tolerance oracle (today).** Not a training run: inject
  calibrated noise (white and temporally-correlated) into B's conditioning at
  eval time and trace metrics vs conditioning error.

## 2. Things which didn't work

- **Honest feed-back (C) is a net negative:** A beats C on all 8 metrics.
  Conditioning on a wrong pose is worse than no conditioning.
- **Every honest GRU arm closed ~0% of the gap.** Across the entire
  A/G/F/R grid, the best arm recovered ~3% of the C→B distance; win-rates vs
  C were coin flips. The oracle arms recovered 83–93% with the same plumbing.
- **A lever:** residual+velocity (A4) was most consistent but still capped at
  ~0.85× of a trivial "reuse last pose" baseline — far from the prize.
- **G lever:** no aggregate effect; the end-to-end variant (G2) never helped
  and caused the worst training blowup.
- **R lever:** iterating the cell was worthless — an "anytime" sweep forcing
  1/2/4/8/16 iterations at eval showed no trend. The apparent R8 win was the
  loss-**weighting** side effect of its gamma sum (4.16× auxiliary gradient),
  not iteration. Iteration also destroyed the recurrence (the hidden state
  went stateless).
- **F lever:** the channel was provably *live* (corrupting it at eval hurt by
  50–90%) yet bought no metric win. Mean-pooled features from a
  translation-equivariant encoder keep roughly 1–2 of the 6 motion degrees of
  freedom — alive but starved of the right information. The two newest
  variants (raw ResNet-18 / DINOv2 features, scored this morning) differ from
  each other by less than the noise floor: the verdict stands.
- **Raw GT at the GRU input made things worse (−55% of the gap).** The
  conditioning path has zero scale invariance; a numerically perfect pose in
  the wrong scale loses to a stale pose in the right scale.
- **Abstention gating was demoted, and rightly so:** an oracle gate beats A
  for *every* arm (17.4% closure), but the prize exists only because the
  corrector is broken, and it masks the defect. Confirmed today from the other
  side: per-scene harm is **unpredictable** from trajectory-only features
  (classifier AUC 0.50 on 4292 scenes) — an honest gate has nothing to read.

## 3. Why they didn't work

One theorem explains nearly everything. The pose the GRU must produce
decomposes as:

> GT(x) = previous head pose ∘ true motion ∘ **accumulated drift**

The GRU's inputs — fed-back pose, its velocity, pooled appearance — are all
functions of the model's **own trajectory**. Drift is precisely the gap
between that trajectory and reality, so it leaves **no signature in any of
those inputs**. It is not hard to learn; it is information-theoretically
absent. And drift dominates the auxiliary loss ~13:1 — even a *perfect*
velocity extrapolator recovers only 20–25% of the fed-pose error.

The A/G/F/R grid was therefore an exhaustive search of a function class that
provably does not contain the target. Capacity, learning rate, saturation,
head expressibility — all measured, all adequate, all irrelevant.

Secondary mechanisms made it worse:
- **Training signal mispriced:** only the last 4 of 16 TBPTT chunks are
  supervised, pricing the learnable (velocity) skill at ~6% of the gradient —
  and teaching a late-sequence correction that is actively misapplied to
  early views (the direct mechanism behind "conditioning hurts").
- **Rotation — where B's benefit lives — gets ~11% of the aux loss.**
- **Noise floor:** median arm-to-arm ATE scatter is 0.00281 (all of it
  training variance — the eval harness re-scored byte-identically,
  4292/4292), so typical lever "effects" (~0.004) were never distinguishable
  from run idiosyncrasy in the first place.

## 4. Things we learned / positives

- **The mechanism works; only the input was missing.** The oracle's 83–93%
  recovery proves conditioning, memory, ray-building and the GRU pathway are
  all sound. The problem was always *what the GRU is asked to see*.
- **The probe-pass gives it something real to see.** A pose-free decode of
  the current frame is the first closed-loop input with measured drift
  information: it improves the fit beyond velocity with confidence intervals
  excluding zero, its trained version clears a placebo control
  (ddR² +0.157, CI [+0.09, +0.22]), and corrupting it degrades the committed
  poses by 40–50% — the GRU demonstrably *uses* it.
- **Today's noise-tolerance oracle removed the biggest fear.** Tracing B's
  metrics against injected conditioning error showed: the response is
  graceful and monotone (no cliff — partial accuracy buys real metric gains);
  there is **no poison region** (even conditioning as wrong as the honest
  head's own error never drops B below A); and temporally-correlated error —
  the kind a closed-loop GRU actually makes — is 2.6× *more* tolerable than
  white noise on ATE and nearly free on RPE. The system operates on the
  forgiving side of the curve.
- **Method lessons that now pay rent:** run the oracle first (one arm
  localized the failure better than the whole grid); decompose the target
  before building the module; pre-register readings before numbers land
  (five inherited estimates failed on measurement; the pre-registered
  determinism prediction held exactly); magnitude comparisons are the wrong
  test for information (decorrelated error is valuable even when larger);
  check the weight-norm before trusting any falsifier; normalized losses can
  report wins on inputs that got worse — keep a GT-scale readout beside them.
- **Infrastructure now trustworthy and cheap:** byte-deterministic 4292-scene
  eval (all scatter is training), calibrated noise-injection instrument,
  placebo/shuffle probe battery, and a noise floor that tells us exactly what
  effect size is claimable.

## Where this stands today

A 50-epoch, 32-GPU, lr 1e-5 finetune of the probe-pass arm
(`captain_gru_v3_a4_g3_r8_refine_finetune` — a single-variable change vs the
scored r8 arm) launched this morning behind all pre-registered gates, with a
mid-run kill gate at checkpoint 10 and a pre-registered scoring rule
(per-scene win% vs C on ATE and rotation: >54.2% = progress, >63.0% = beats
A; depth must stay in the family band). Honest caveat, priced in advance: the
probe's naively-implied effect (~0.001 ATE) is below the 0.00281 noise floor,
so the arm is betting that training-time absorption amplifies the observation
— the causal evidence (40–50% shuffle dependence) says it does, the table
will say by how much.
